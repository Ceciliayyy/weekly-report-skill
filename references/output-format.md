# 输出格式

先确认用户公司的字段。用户提供了周报模板时，字段名称、顺序、必填项和空值写法一律以模板为准；没有提供时使用本文件的默认格式。

## 默认字段

```text
汇报时间
本周工作成果
重要工作进展
未完成事项&原因说明
下周工作计划
其他
```

如果模板另有“支撑材料”“风险与协调”等字段，保留这些字段，不要擅自合并或改名。

用户未提供模板时，默认只输出下列六个字段。不要改写为“报告时间”“工作总结”等同义词，也不要自行添加“备注”“汇报周期”“说明”等字段。

## 默认输出：钉钉粘贴版

默认只输出一份可直接复制到钉钉的纯文本。使用中文编号；不要使用 Markdown 标题、加粗、表格、代码块或内部工作说明。

```text
汇报时间：YYYY-MM-DD

本周工作成果：
1. 项目或业务模块名称
（1）工作结果或推进状态
（2）工作结果或推进状态

2. 项目或业务模块名称
（1）工作结果或推进状态

重要工作进展：
无

未完成事项&原因说明：
未说明

下周工作计划：
未提供

其他：
-
```

规则：

- `汇报时间`优先使用用户明确给出的提交日期；未提供时默认采用汇报周期的结束日期，并在审阅说明中注明这一处理。不得使用系统当前日期，除非用户明确要求以生成当天作为汇报日期。
- 业务模块名称由本次记录动态生成，不沿用示例项目。
- 模块内按依赖关系和业务推进顺序排列：调研/方案 → 实施/处理 → 验证/结论 → 交付；不按日期排列。
- 同一事项只出现一次。
- 重要工作进展有内容时使用“（1）（2）”编号；下周工作计划有内容时使用“1. 2.”编号，即使只有一条也编号。
- 没有重要进展时，按模板省略、写“无”或写“-”；不要为了填满栏目重复成果。
- 没有任何其他事项时，按模板写“无”或“-”；不要把未归类的重要内容塞进“其他”。
- 默认空值写法：重要工作进展无内容写“无”；未完成事项默认写“未说明”，只有原始记录明确表示没有未完成事项时才写“无”；下周计划未提供写“未提供”；其他无内容写“-”。不要使用长破折号代替。
- 每个字段尽量控制在一屏可读；若目标是钉钉日志字段，注意单字段通常不超过 1000 字符。

## 审阅稿

用户要求预览、审阅、对照或校验时，在粘贴版之外或之前输出 Markdown 审阅稿。审阅稿可以包含：

- 周报正文。
- 项目归并说明：哪些日期被合并、依据是什么。
- 数量计算说明：例如 `20 + 15 + 30 + 25 = 90 份`。
- 待确认事项：缺少日期、项目归属、完成状态、冲突信息、可能重复的数据。

不要把审阅说明混进粘贴版。若用户没有要求文件，直接在对话中输出，不必创建临时文件。

## 各字段写法

### 本周工作成果

- 只写实际发生的工作和可确认的状态。
- 先写对象或工作，再写动作和结果；一句话表达一个结果。
- 可以使用“完成、启动、提交、开展、形成、调整、验证”等动词，但必须忠实于原始记录。
- 保留数量、轮次、进度、范围和里程碑。
- 同一对象合并成一句，避免重复名词；正式稿只保留支持结论的关键证据，测试通道、环境清单等过程明细放入审阅稿。
- 零散事务合并到“其他工作”，但重要的项目工作不能因为不好归类而放入其他。

### 重要工作进展

只选择 0—3 条满足以下至少一项的内容：

- 关键节点完成或外部交付提交。
- 重要方案、范围或优先级已经确定。
- 重大阻塞解除。
- 关键结果经过验证。
- 对后续进度或资源安排有实质影响。

如果某条内容只是“本周工作成果”的重复，删除它。无法确定重要性时，保留在成果部分即可。

### 未完成事项&原因说明

只写原计划在本次汇报周期内完成、但实际没有完成的事项。格式优先写成：

```text
事项：原因；影响或需要支持（如有）
```

不要把以下内容误写为未完成事项：

- 正常排到下周的工作。
- 尚未到计划截止时间的工作。
- 只是仍在持续推进且没有本期交付承诺的工作。

缺少原因时写“原因未说明”，不要自行归因。只有明确没有未完成事项时才写“无”。如果记录只说明某事项“等待反馈”或“仍在进行”，但没有证据表明它原本应在本周期完成，不要把它归入未完成事项；保留在成果部分，并在待确认中询问完成期限。

已确认的风险或外部依赖，如果模板有独立字段，就写入独立字段；没有独立字段时，按用户现有习惯放入合适位置，并在审阅说明中解释，不要静默隐藏。

### 下周工作计划

- 只使用记录中明确出现的下周安排。
- 每条动词开头，尽量说明对象和预期动作，不补写日期或成果承诺。
- 没有安排时写“未提供”并放入待确认，不凭空生成计划。

### 其他

- 放低权重、相互独立且不适合归入项目的杂事。
- 不放置重要的项目成果、风险或未完成事项。
- 无内容时按模板写“无”或“-”。

## 语言和长度

- 目标是一页或一屏可读完；不设死板的字数上限。
- 信息密度优先于字数。每句话至少提供一个事实、状态、判断或明确的下一步。
- 能用一句话表达的结果不拆成多条；同一名词不在相邻条目中反复出现。
- 不使用“重大突破”“圆满成功”“奠定坚实基础”等空泛评价，除非原始记录提供了可核验的依据。
- 不写过程流水账；只有在过程改变了结果或风险时才保留过程。

## 最终自检

在输出粘贴版之前，确认：

- 字段名与用户模板一致。
- 项目中不混入其他项目的成果。
- 同一事项没有重复出现。
- 所有数量有依据，合计没有重复计算。
- 未完成、风险、正常跨周工作没有混淆。
- 重要进展不是成果清单的复述。
- 下周计划没有编造。
- 粘贴版没有 Markdown 标记和内部推理说明。
- 待确认内容只出现在审阅说明，不混入正式稿。
